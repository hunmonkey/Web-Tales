============================================================
Tales(Web-Tales) 개선 계획서
============================================================

작성일   : 2026-06-20
대상     : 황재훈 님(오너)
목적     : 현재 Tales를 꿀뷰(Honeyview) / YES24 eBook / 크레마(Crema)
           수준의 E-Book·만화·그림 뷰어로 끌어올리기 위한 진단과 개선 로드맵
분석근거 : 실제 코드(komga / komga-webui / docs) 직접 확인 + 상용 뷰어 벤치마크
           (꿀뷰, Kavita, YES24, 크레마, 리디, epub.js, Readium)

주의: 이 계획서는 "닫힌(closed)" 프로젝트를 '범위를 한정해 재개'하자는 제안이다.
      Phase 1~3로 범위를 못 박지 않으면 작업 범위가 무한 확장된다.


------------------------------------------------------------
0. 한 장 요약 (TL;DR)
------------------------------------------------------------
- "엉성함"은 기능 몇 개 누락이 아니라 '리더 코어의 구조적 미완성 + 책장 경험 부재'가
  겹친 결과다.
- 그러나 기반(Komga 포크 + 어댑터 구조 + 타이포·인코딩·위치복원)은 나쁘지 않다.
  전면 재작성은 불필요하고 위험하다.
- 권고 경로: 리더 코어만 컴포넌트 분해(Phase 0) → 만화 상호작용 보강(Phase 1)
  → EPUB 어댑터 편입(Phase 2) → 독서 보조(Phase 3) → 책장 경험(Phase 4)
  → 포맷·성능 차별화(Phase 5).
- 가장 먼저: Quick Wins(줌/패닝/회전/TXT검색/밝기/썸네일/한글폰트)로 체감을 빠르게 회복.


------------------------------------------------------------
1. 진단 — 왜 엉성하게 느껴지는가 (근본 원인 6가지)
------------------------------------------------------------

1) 리더 코어의 상호작용 빈곤
   - 상용 뷰어의 기본 3종(자유 줌 / 드래그 패닝 / 90도 회전)이 통째로 없다.
   - 근거: komga-webui/src/shelfview/functions/reader-input.ts 의 키 동작은
           NEXT/PREVIOUS/FIRST/LAST/SHOW_SHORTCUTS 뿐. zoom/rotate/pan 로직 없음.
   - 확대는 설정창 fixedPageScale 슬라이더 80~180%(5% 단위)가 전부.
     → '뷰어를 조작하는 맛'이 안 난다.

2) 단일 거대 컴포넌트가 확장의 병목
   - komga-webui/src/shelfview/views/ShelfViewReaderShell.vue = 2724줄.
   - 고정페이지·텍스트·혼합 3종 + 필터·테마·책갈피·설정 서랍이 전부 한 파일에 인라인.
   - 줌·썸네일·검색 같은 새 레이어를 붙일 자리가 없고, 손대면 부작용이 커서
     기능 추가가 사실상 멈춰 있다.

3) 독서 보조 차원의 전면 부재
   - 매니페스트 capabilities.search 가 모든 포맷에서 false 로 하드코딩.
     (komga/.../shelfview/interfaces/api/ShelfViewManifestController.kt)
   - 본문 검색·텍스트 선택·하이라이트·메모·목차(TOC)·사전·TTS 전부 비어 있음.

4) EPUB 공백 = 한국 전자책 미대응
   - 한국 소설·문학의 사실상 표준 EPUB을 백엔드가 명시적으로 거부(BAD_REQUEST)하고
     레거시 komga-webui/src/views/EpubReader.vue 로 분기.
   - 같은 서재 안에서 포맷마다 다른 리더·다른 설정·다른 책갈피 → 일관성 붕괴.

5) 수집·발견 경험의 협소함
   - 서버 사전 스캔 + .shelfview-book 수동 마커 전용.
   - 꿀뷰식 '폴더 즉시 열기', 자동 폴더 감지, 웹 업로드가 없어 진입 장벽이 높다.

6) 책장이 stock Komga 그대로
   - 리더만 Tales이고 서재 화면(DashboardView.vue 등)은 Komga 기본 UI.
   - ShelfView가 라우터에 추가한 것은 /read-v2/:bookId 리더 한 곳뿐. 정체성이 갈린다.

※ 본질: 위 격차가 '프로젝트 종결(closed)' + 5개 핵심 항목 deferred로 동결돼 있다.
        엉성함은 미완성이 아니라 '의도적으로 멈춘 상태'다.

2. 현재 강점 (유지할 것 — 전부 갈아엎지 말 것)
------------------------------------------------------------
- 텍스트 타이포: 글자크기/줄간격/자간/어간/본문폭/여백/문단간격/굵기/글꼴5종/정렬.
  (YES24보다 세밀함) — functions/text-reflow-view.ts, ShelfViewReaderShell.vue
- 만화 보기 기본기: 단면/양면/연속, LTR/RTL, 4종 맞춤(화면/폭/높이/원본),
  6종 색보정 필터 프리셋 — functions/fixed-page-view.ts, image-filter-presets.ts
- 한글 인코딩: auto→UTF-8→EUC-KR 후보 + 수동 재시도 (구형 한국어 TXT에 강함).
- 위치 복원·다중 책갈피: 문단/문자 오프셋 Locator, 사용자별 동기화 (SV-300~304).
- 안정성: 손상/권한/네트워크/인코딩 오류 복구 UX, 페이지 단위 재시도 (SV-601).

3. 영역별 격차 (벤치마크 대비)
------------------------------------------------------------

[3-1] 만화·이미지 리더 (vs 꿀뷰 / Kavita)
  기능                              상태            심각도
  ---------------------------------------------------------
  자유 줌(휠/핀치/더블탭)           없음(슬라이더만)  높음
  드래그 패닝                       없음             높음
  90도 회전                         없음(계획엔 있었음) 높음
  썸네일 필름스트립 / 페이지 점프    없음(*백엔드 썸네일 미사용) 중간
  슬라이드쇼 자동 넘김              없음             중간
  양면 '표지 단독' 토글             없음(짝수 시작 고정) 중간
  웹툰 전용 연속 모드               부분(일반 연속만)  중간
  WebGL 샤프닝/화질 개선            없음(deferred)    중간
  (*) manifest의 thumbnailEndpointTemplate 필드는 존재하나 리더 UI에서 미사용.

[3-2] 텍스트·EPUB 리더 (vs YES24 / 크레마 / 리디)
  기능                  상태                       심각도
  ---------------------------------------------------------
  EPUB 렌더링           없음(백엔드 거부)            치명적
  본문 검색             없음(search=false)          높음
  목차(TOC) 이동        없음                        높음
  하이라이트/형광펜      없음                        높음
  메모/노트             부분(DB note 컬럼만, UI 없음) 중간
  단어 사전             없음                        중간
  TTS 음성 읽기         없음                        중간
  TXT 밝기 조절         없음(만화엔 있음)            높음
  한글 웹폰트 번들       부분(OS 설치 폰트 의존)       높음
  세로쓰기              없음                        낮음

[3-3] 책장·수집
  - 브라우저 로컬 파일 열기: 없음(deferred)
  - 폴더 자동 감지: 없음(.shelfview-book 마커 필수)
  - 웹 UI 파일 업로드: 없음
  - 고급 패싯 필터/스마트 컬렉션/저장 검색: 약함
  - '이어서 읽기' 캐러셀/진행률 배지/'나중에 읽기' 큐: 약함

[3-4] 포맷
  - RAR/CBR 혼합 콘텐츠: 없음 (고정페이지 RAR은 Komga로 가능, 혼합은 불가)
  - 7z / LZH / TAR: 없음 (7z는 중첩 차단 목록에만 존재)
  - PDF.js 텍스트레이어/검색/링크: 없음(deferred), 현재 PDF는 페이지 이미지 렌더만
  - 최신 이미지(AVIF/JXL): 없음
  - MOBI/AZW: 없음 (EPUB 변환 권장)
  - 오디오북: 없음 (우선순위 낮음)

[3-5] UI/UX·구조
  - 페이지/테마 전환 애니메이션: 없음(즉시 전환)
  - 다크모드 일관성: 리더는 하드코딩 색(#f4ecd9/#14171c/#000000),
    앱은 Vuetify 테마 → 토글이 따로 논다
  - 모바일 반응형: @media(max-width:600px) 1개만, breakpoint 분기 미흡
  - 책장 브랜딩: Tales 로고만 추가, '내 서재' 감성 없음
  - Rule_UIUX.txt: 다수 섹션이 제목만 있고 본문 공백(기준선 미완성)


------------------------------------------------------------
4. 개선 로드맵
------------------------------------------------------------

[4-1] Quick Wins (각 1~수일, 신규 의존성 거의 없음)
  이것만 해도 '엉성함'의 절반이 사라진다. 대부분 CSS transform / 타이머 / 기존 UI 재사용.

  QW-1. 휠 줌 + 드래그 패닝  (transform: scale()/translate())   ── 1순위 체감
  QW-2. 90도 회전 버튼 + R 단축키  (transform: rotate())
  QW-3. TXT 본문 검색  (서버가 이미 문단 배열 보유 → 클라이언트 검색+점프, search=true)
  QW-4. TXT 리더 밝기 슬라이더  (만화용 밝기/대비 슬라이더 UI 재사용)
  QW-5. 썸네일 필름스트립 + 페이지 번호 직접 점프  (미사용 thumbnailEndpoint 활용)
  QW-6. OFL 한글 웹폰트 2~3종 번들  (나눔/코펍바탕 등 — 기기 무관 동일 가독성)
  QW-7. 양면 '표지 단독' 토글  (펼침 정렬 정확도)
  QW-8. 이미지/만화 슬라이드쇼(자동 넘김) 모드  (next()에 타이머)

[4-2] Phase 0 — 리더 코어 분해 (선행 전제)
  목표: ShelfViewReaderShell.vue 2724줄을 어댑터 타입별 자식 컴포넌트로 분해해
        이후 모든 기능 확장의 자리를 만든다.
  항목:
   - FixedPageReaderPanel.vue / TextReaderPanel.vue / MixedReaderPanel.vue 분리
     (각 600줄 이하 목표, shell 400줄 이하)
   - ReaderToolbar.vue, 북마크/설정 서랍 독립 컴포넌트화, props/emit 통신만 허용
   - 줌/패닝/회전 상태를 담을 ViewportController 추상화 도입(Phase 1이 여기 얹힘)
   - 기존 리더(EpubReader.vue 등)는 폴백 유지, 분해 전후 동작 동일성 회귀 테스트
  주의: '관련 없는 리팩터링 금지' 규칙에 따라 동작 변경 없는 순수 분해로 한정하고
        테스트로 보증한다.

[4-3] Phase 1 — 만화·이미지 리더 강화 (최우선 체감)
  목표: 꿀뷰/YES24 수준의 뷰어 상호작용 3종 세트 + 탐색성으로 엉성함을 가장 빨리 제거.
  항목:
   - 휠/핀치/더블탭 줌 + 드래그 패닝 (Phase 0 ViewportController에 구현)
   - 90도 단위 회전 + 회전 후 fit 재계산
   - 썸네일 필름스트립 + 페이지 번호 직접 점프
   - 양면 '표지 단독' 토글, 웹툰 전용 연속 모드(간격 제거·폭 100% 스티칭)
   - 슬라이드쇼(자동 넘김) 모드, 회전/줌/점프 키보드 단축키 보강
  근거: 두 벤치 리서치가 공통으로 relevance '높음'·보유 '없음'으로 지목.
        대부분 CSS transform/타이머만으로 신규 의존성 없이 구현 → impact 대비 effort 최고.

[4-4] Phase 2 — EPUB 통합 리더 (한국 전자책 대응)
  목표: 백엔드 BAD_REQUEST 거부를 풀고 EPUB을 Tales 통합 리더의 매니페스트 종류로 편입.
  항목:
   - EPUB_REFLOWABLE 매니페스트 종류 신설, 서버에서 목차(TOC)·스타일·메타데이터 제공
   - epub.js 또는 foliate-js 기반 EPUB 어댑터를 Phase 0 분해 구조 위에 추가
     (라이선스 BSD/MIT/Apache 사전 확인 필수)
   - 기존 EpubReader.vue는 검증 완료 전까지 폴백 유지, 설정·진행률·책갈피 호환성 테스트
  주의: EPUB 도입은 되돌리기 어려움 → 구현 전 ADR 작성(CLAUDE.md 규칙). XL 규모.

[4-5] Phase 3 — 텍스트 독서 보조 (검색·하이라이트·목차·사전·TTS)
  목표: search=false 로 비어 있는 독서 보조 차원을 채워 학습·정독 용도를 가능케 한다.
  항목:
   - 목차(TOC): EPUB는 nav 기반, TXT는 '제N장/Chapter/* * *' 휴리스틱 감지 + 점프
   - 하이라이트·메모: 기존 책갈피 테이블에 highlight_start/end_char·color·annotation
     컬럼 확장 (새 테이블 불필요 — 문자 오프셋 Locator가 이미 있음)
   - 본문 검색을 EPUB/PDF 텍스트 레이어로 확대 (PDF.js는 ADR 후속)
   - 한글 사전 연동(우리말샘 OpenAPI 등) 선택 후 팝업, 진행률 '약 N분 남음' 표시
   - TTS(Web Speech API) 문단 단위 재생 — 선택 기능, 우선순위는 사전/하이라이트 뒤
  근거: 백엔드 책갈피 테이블에 note 컬럼 + 문자 오프셋 Locator가 이미 있어
        하이라이트가 저비용 확장 가능.

[4-6] Phase 4 — 책장·수집 경험 (서재 정체성)
  목표: stock Komga 그대로인 책장에 Tales 고유의 '내 서재' 큐레이션과 입수 편의를 더한다.
  항목:
   - ShelfView 대시보드: 이어서 읽기(최근 위치) 캐러셀, 진행률 배지,
     미완독/완독 필터, '나중에 읽기' 큐
   - 이미지 폴더 자동 감지 옵션(scanImageDirectoryAuto, 기본 off, 마커 선택사항화)
   - PDF 속성(제목/저자) 자동 추출로 메타데이터 기본값 채우기 (PDFBox 등)
   - 메타데이터 대량 편집 UI / CSV 임포트, 고급 패싯 필터·저장 검색
   - 다크모드 일관성 통일 + 로딩/에러 상태 시각 피드백 개선
  주의: 자동 폴더 감지·메타 추출은 오인식 위험 → 리더 강화 이후로 배치.

[4-7] Phase 5 — 포맷 확장·성능·화질 (차별화)
  목표: RAR/CBR·최신 이미지 포맷·만화 화질 개선·서버 성능으로 상용 뷰어 대비 차별점.
  항목:
   - RAR/CBR 혼합 콘텐츠 지원 평가 (Apache Commons Compress, 보안 ADR 선행)
   - WebGL 샤프닝/적응형 흑백 부활 — 저해상도 스캔 만화 차별화 (deferred 재개)
   - 최신 이미지 포맷(AVIF/JXL) 평가, 페이지 렌더링 캐시 다층화·프리페치 확대
   - 전역 동시성/메모리 한계 설정 (Unraid 저사양 대비), PDF.js 직접 렌더링 ADR
   - 로컬 파일 열기/오프라인 PWA(zip.js)는 모바일 수요 검증 후 선택 도입
  주의: 대부분 effort L~XL + 보안 ADR 필요. 핵심 경험(Phase 1~4) 정착 후 진행.

5. 핵심 전략 결정 — 전면 재작성 금지, "리더 코어 분해 + 어댑터 확장"
------------------------------------------------------------
권고: '국소적 재설계 + 점진 개선' 혼합.

- 분해는 전제조건: 2724줄 단일 컴포넌트에 줌·썸네일·검색을 계속 인라인하는 것은
  물리적 한계. 단 이는 국소 재설계(컴포넌트 분리)이지 재작성이 아니다.
- EPUB/PDF.js는 '어댑터 추가'로 접근: 이미 FixedPage/TextReflow/MixedContent
  어댑터 패턴이 있으므로 EPUB_REFLOWABLE 매니페스트 + epub.js 어댑터를 얹는 것은
  점진 개선의 연장선이다.
- Komga 자산은 유지: 스캐너·미디어분석·페이지스트리밍·인증·권한·진행률을 버리면
  1인 개발로 감당 불가. CLAUDE.md도 Vue3/Vite/Spring 마이그레이션을 오너 승인 없이 금지.

결론: 리더 코어만 분해(Phase 0) → epub.js/PDF.js는 어댑터로 ADR 기반 편입
      → 나머지는 Komga 위 수직 기능 조각으로 점진 확장.
      이것이 1인 개발·업스트림 병합성·라이선스 제약을 모두 만족하는 유일한 현실 경로다.
      전면 재설계는 권하지 않는다.
