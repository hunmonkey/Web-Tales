============================================================
사용자 추가 기능 점검 계획 및 방법 (2026-06-24)
============================================================

[요청]
"사용자를 추가할 수 있게 해줘"
→ 현재 증상: 메뉴는 보이는데 추가가 안 됨 (관리자 계정으로 로그인된 상태)

------------------------------------------------------------
1. 조사 결과 요약 (코드 정적 분석)
------------------------------------------------------------
사용자 추가 기능은 이미 완전히 구현되어 있으며, 코드 연결 흐름에
끊긴 곳은 발견되지 않음. 주요 경로는 아래와 같음.

[프론트엔드]
- 메뉴 노출: tales-webui/src/views/HomeView.vue (L213)
  → v-if="isAdmin" 조건. 관리자만 설정/사용자 메뉴가 보임.
- 라우트: tales-webui/src/router.ts (L91~101)
  → /settings/users (adminGuard)
  → 자식 라우트 /settings/users/add → UserAddDialog.vue
- 화면: tales-webui/src/views/SettingsUsers.vue
- 목록 + "+" 추가 버튼: tales-webui/src/components/UsersList.vue
  → "+" 버튼은 :to="{name: 'settings-users-add'}" (L92)
  → 자식 라우트 렌더용 <router-view/>가 L118에 존재함 (정상)
- 추가 다이얼로그: tales-webui/src/components/dialogs/UserAddDialog.vue
  → 확인 시 store dispatch('postUser') 호출
- store action: tales-webui/src/plugins/tales-users.plugin.ts (L50)
  → service.postUser(user) 후 getAllUsers()로 목록 자동 갱신
- service: tales-webui/src/services/tales-users.service.ts (L77)
  → POST /api/v2/users

[백엔드]
- tales/src/main/kotlin/org/tales/interfaces/api/rest/UserController.kt (L88)
  → @PostMapping, @PreAuthorize("hasRole('ADMIN')")
  → UserCreationDto 검증 후 userLifecycle.createUser(...) 호출

[결론]
- 코드 자체는 정상. 새로 만들 필요 없음.
- "추가가 안 됨"은 정적 분석으로 안 보이는 런타임 문제일 가능성이 큼.
  → 실제 클릭 시 증상/에러를 확인해야 원인 특정 가능.

------------------------------------------------------------
2. 원인 후보 (런타임)
------------------------------------------------------------
(A) 다이얼로그가 안 뜸        → 라우팅/렌더 문제
(B) 확인 시 빨간 에러 토스트  → 백엔드 응답 코드별로 분기
     - 403 Forbidden  : 로그인 계정이 실제로는 관리자 권한이 아님
     - 400 Bad Request: 이메일 중복 / 검증 실패 / roles 값 불일치
     - 500 Server Err : 백엔드 예외 (DB, createUser 로직 등)
(C) 반응 없이 창만 닫힘       → 요청은 갔으나 목록 갱신 실패 등

------------------------------------------------------------
3. 증상 확인 방법 (재훈 님이 직접 확인)
------------------------------------------------------------
1단계. 설정 → 사용자 화면에서 우측 하단 동그란 파란 "+" 버튼 클릭
       → 이메일/비밀번호/역할 입력 다이얼로그가 뜨는지 확인

2단계. 이메일·비밀번호 입력 후 "확인" 클릭
       → 빨간 에러 메시지가 뜨면 그 전문을 기록

3단계. 브라우저 개발자도구(F12) → Network 탭 열기
       → "확인" 누른 뒤 'users' 요청 찾기
       → 상태 코드(200/400/403/500)와 응답 본문(Response) 기록

위 1~3단계 결과를 알려주시면 원인을 한 곳으로 좁혀 수정함.

------------------------------------------------------------
4. 원인별 수정 계획 (확인 후 진행)
------------------------------------------------------------
- 403 인 경우:
  → 현재 로그인 계정의 roles 확인.
  → 첫 사용자/관리자 지정 흐름(InitialUserController.kt) 점검.
  → 필요 시 해당 계정에 ADMIN 권한 부여.

- 400 인 경우:
  → 응답 메시지로 구분.
    · 이메일 중복 → 다른 이메일로 안내
    · roles 값 오류 → 프론트 UserRoles enum과 백엔드 UserRoles 매핑 점검
    · 검증 실패 → UserCreationDto 검증 규칙 확인

- 500 인 경우:
  → 서버 로그(docker logs Web-Tales) 확인 후 백엔드 예외 수정.

- 다이얼로그 자체가 안 뜨는 경우:
  → 라우트/렌더 경로 재점검 (router.ts ↔ UsersList router-view).
